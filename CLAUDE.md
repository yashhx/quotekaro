## What this is
A single-file React prototype of a SaaS for small Indian CNC job-shops (Delhi NCR).
Built by Yash — solo, bootstrapped, Faridabad. Everything lives in `src/App.jsx`.
It began as a **quotation maker**; field visits are pushing it toward a **quote TRACKER** (pipeline-first). See "Strategic context" — it decides what's worth building.

## Commands
- `npm install` — setup
- `npm run dev` — local dev server (Vite)
- `npm run build` — production build to `dist/`
- Deploy = drag `dist/` folder onto Netlify. PWA installable via Add to Home Screen.

## Architecture
- **One file:** `src/App.jsx` (~1,400 lines). All components, all CSS (in the `const CSS` template literal), all icons (inline SVGs in `const I`). Keep it single-file unless explicitly asked to refactor.
- **Storage:** localStorage via a small async `storage` shim at the top of App.jsx (`get/set/delete`). Keys: `quotekaro:v4` (shop data), `quotekaro:auth:v1` (account). If you change a schema, bump the key version to avoid stale-data crashes.
- **Auth is SIMULATED.** Any phone + any 4-digit OTP works; any username/password works. This is deliberate (no backend yet). Real Firebase/Razorpay hooks are marked with `/* HOOK */` comments. Do NOT wire real auth/payments unless explicitly asked.
- **PDF quotations:** jsPDF loaded from CDN at runtime. PDFs use "Rs " not "₹" (glyph missing in core PDF fonts) — keep it that way.
- **PWA:** `public/manifest.json`, `public/sw.js`, `icon-192/512.png`.
- **Subscription page**: ONE plan - Rs 999/month, everything included (changed 2026-07-16 from the old 3-tier demo; PLANS has a single "full" entry, legacy plan ids resolve to it). Still simulated, demo-labeled.

## Kanta parchi (weighbridge slip) - SHIPPED (2026-09-21, user ask)
Scrap dealers weigh at a **dharam kanta**: the loaded truck is weighed (GROSS), the empty truck is weighed again after unloading (TARE), and the printed slip carries net = gross - tare in **KILOGRAMS**, with a slip serial, vehicle number and timestamp. The app works in MT, so kg -> MT conversion happens in exactly ONE place (`parchiMT`, `KG_PER_MT`) - never inline.
- Yard stock page: "Kanta parchi daalo" opens the camera (`capture="environment"`), the photo is downscaled to **1100px q0.62** (the slip's digits must stay readable - a 240px thumbnail is useless) and a bottom sheet asks, in order: **1. maal aaya ya gaya** (nothing else renders until this is answered), 2. material, 3. gross/tare/net kg (net auto = gross - tare, or type the printed net; the live "12,540 kg = 12.54 MT" line is the confirmation), party / slip no / vehicle / slip date, then **4. an explicit "stock me jodein / ghatayein?" Haan-Nahi** whose Haan button spells out "+12.54 MT" or "-12.54 MT".
- `data.stock.parchis` (additive, v5 kept) = {id, photo, dir "in"|"out", cat, kg, gross, tare, party, ref, vehicle, at, addedAt, linkId}. Applying a parchi CREATES a normal `stock.ins`/`stock.outs` entry carrying `fromParchi`, and `linkId` points back at it - so `stockCalc` needed no change and the two can never drift. "Nahi - sirf record" saves the parchi with linkId null (folder only, stock untouched); the viewer toggles it either way.
- **Three warnings that stop a corrupted yard total** (each shown in the sheet, none blocking): duplicate slip number; an "out" parchi for a party that already has a Truck board trip TODAY (that trip already subtracts - keep it record-only); a parchi older than that material's last kanta check (baseline rule means it cannot move today's stock).
- Parchi folder = the whole history grouped by day (AAJ / KAL / date), each row thumbnail + MT + AAYA/GAYA + party/slip/vehicle + "STOCK ME" vs "SIRF RECORD"; tap = full-screen slip with add/undo, "Photo hatao" (keeps the entry, drops the image) and delete (removes the linked stock entry too).
- **Parchi photos live in IndexedDB, NOT in the data blob (2026-09-21):** store `photos` in DB `trackrakho`, key `ph_<parchiId>`, value a plain Blob (`photoPut/photoGet/photoDel`, every call degrades to null so a private window still works). The parchi record keeps `img` (the key) + `bytes`; the old inline `photo` data URL is still rendered and is migrated into IndexedDB once, quietly, by an effect on the Yard stock page. `ParchiImg` resolves either shape and revokes its object URL on unmount. Why: base64 adds ~33% and costs 2 bytes per character in Safari's UTF-16 localStorage, and in cloud mode the whole blob - photos included - was rewritten to Postgres on every debounced save. Measured after the move: three slips = 31 KB of blobs, and the localStorage blob fell to 10 KB. **The trade, said in the UI ("Parchi ki photo isi phone me rehti hai"): slip images are per-device; the parchi entry itself still syncs.** Quote photos (`q.image`) deliberately STAY inline - they are small and their whole point is syncing with the pipeline. Supabase Storage remains the answer for cross-device images. The folder header shows "N parchi - X MB", an amber card appears past 3 MB, and a failed local save now TOASTS "Phone ki storage bhar gayi" instead of dying quietly. Supabase Storage is the real fix and is still the documented next step for all media.
- Verified in preview: gross 16540 - tare 4000 = 12.54 MT subtracted (58.4 -> 45.86), undo restores 58.4, re-apply returns 45.86, an "in" parchi saved record-only left the total alone and applying it later added 8.2 MT (45.86 -> 54.06). NOT built: AI reading of the slip (no endpoint takes an uploaded image - read-media.js is mediaId-only), and no kat/shortage deduction field.

## Domain logic (costing) — the math is settled, don't reinvent
- Quote per piece = material (kg × ₹/kg) + machine (cycleMin/60 × machine ₹/hr, + setupMin/60 × rate ÷ qty) + labour (manualMin/60 × labour rate) + tooling → + overhead% → + margin% → price/pc; total = price × qty (+ GST display).
- True hourly-rate calculator = depreciation + power (kW × ₹/unit) + operator + maintenance, all per monthly working hours. Seeded example: VMC 850 ≈ ₹366/hr.
- **Multi-machine rule (from a real shop visit):** when one operator runs N machines, his salary is split — `operator cost ÷ N` folds into the MACHINE hourly rate ("loaded rate"); manual/hands-on minutes stay at FULL labour rate (he's dedicated then). A "machines per operator" field in the rate calculator is a known TODO.
- The app does **not** predict cycle time. The user supplies it; the app does the money math. Never write UI copy claiming it calculates machining time.
- Keep seeded sample data consistent: Sharma Precision Works; Gland Nut — 60mm, 200 pcs, ₹174.39/pc, ₹34,878 total.

## Strategic context — read before building ANY feature
Three real shop visits taught us:
1. Shops already quote fine in **Excel**, and their clients often DEMAND the Excel format. A quoting-first app is weak against that.
2. What owners actually liked, unprompted: the **pipeline view** — all quotes with pending/won/lost status.
3. A micro-shop owner suggested the tool may fit **traders** (middlemen) better than shops.

## Conventions & gotchas (bugs we already paid for)
- **The DOCUMENT must never scroll - only `.scr` does (2026-09-21, user: "the app looks so unstable, the whole app goes up along with the bar"):** `.qk-root` used `min-height:100vh` while `.app` used `100dvh`. On iOS `100vh` is the toolbar-HIDDEN height, so the page was always taller than the visible area and every drag slid the entire app - including the absolutely-positioned nav bar. Now `html,body{height:100%}`, `body{overflow:hidden; overscroll-behavior:none}`, `.qk-root{height:100dvh; overflow:hidden}`, `.app{height:100%}`, desktop `min(calc(100dvh - 36px), 940px)`, and `.scr{overscroll-behavior:contain}` so an inner scroller hitting its end cannot hand the drag to the page. Never reintroduce a `100vh` height on the root.
- **Safe areas:** `.app` carries `padding-top:env(safe-area-inset-top)` (installed PWA draws under the status bar - the Setup header was colliding with the clock) and `.pagepad` bottom is `calc(130px + env(safe-area-inset-bottom))`. The nav sits at `max(10px, calc(env(safe-area-inset-bottom) - 16px))`: **do NOT add the bottom inset on top of a gap** (`14px + inset` = 48px on a notched iPhone and the user reported the bar "floating randomly" halfway up). The bar's own 8px padding already keeps the buttons clear of the home indicator.
- **Every page that shows the nav needs the 130px bottom padding.** MachineFloor / TruckBoard / StockYard kept `paddingBottom: 40` from the days when the nav hid itself on those pages; after the 2026-09-19 IA rework the nav is always there and it was covering the last card ("Stock me jodo" was unreachable). Only Subscribe (nav hidden) keeps 40.
- **Photos must be readable, not just recognizable:** `downscaleImage` defaults are 820px q0.6 (was 240px q0.55 - a truck number was unreadable even in the lightbox); parchi slips use 1100px. Pipeline card tiles are 62px, Home rows 54px.
- **Encoding (2026-09-21):** everything encodes to **WebP** when the browser can (`webpEncodes()` asks the canvas once - Safari only learned to ENCODE WebP in 16, older phones fall back to JPEG automatically). A parchi additionally passes `{gray: true}`: black print on white paper carries no colour, so grayscale + `contrast(1.08)` (canvas `ctx.filter`, with a hand-written luminance pass for Safari < 15.4) at q0.55. Measured on a textured slip photo: 53 KB colour JPEG -> **23 KB (-57%)**, digits still crisp. Do NOT grayscale quote photos - those are real photographs of parts and trucks.
- **Rules of Hooks:** every hook must sit above any early `return` in a component. A hooks-after-loading-return bug already crashed this app once.
- **No smart punctuation in source:** em-dashes (—), curly quotes ("" '') inside string literals have broken the parser before. Use ASCII (-, ', ") in code and string content.
- **Service worker must only intercept same-origin GETs** (public/sw.js): Safari fails POST bodies re-dispatched through a SW, which silently killed OAuth sign-in for days. Auth calls, Google APIs and function POSTs must bypass the worker.
- **Google Cloud: enable APIs in the project that owns the OAuth client** (1011022588709, "quotekaro"). An API enabled in another project does nothing; the 403 names the project number - read it.
- **User-facing flows must toast their failures.** The Gmail connect chain failed silently at three different layers and each looked like "nothing happened". Any multi-step connect/save flow: every failure branch gets a specific, actionable toast.
- All styling stays inside the `CSS` template literal or inline styles — no CSS files, no Tailwind.
- Every backtick template must close; run a build (`npm run build`) after sizeable edits to catch parse errors early.
- Small, specific changes over sweeping rewrites. This file is the product's memory — update it when decisions change.
